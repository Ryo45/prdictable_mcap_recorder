# Writer の完全性契約

## 所有権と確定の境界

1. Capture が受理した BufferLease は Queue、Copy Worker、Writer のいずれか一つが保有する。CopyOut が完了した借用枠は返却要求へ進み、置換した Spill の Lease は Writer に保持する。
2. Writer は元 I/O が完了し、カーネルや backend が参照を終えるまで BufferLease を保持する。同期 split と pwritev はどちらも全バイトの処理完了まで Lease を保有する。部分書込みの再開は完了済みバイトの次から行う。失敗・キャンセル・再試行で同じ枠を二重に返却しない。
3. 元 I/O の完了、Device/Spill 枠の返却、データファイルの fdatasync、commit journal の fdatasync は別の事象。データが読み出せることだけから永続化済みと判定しない。

## 正常終了で確認すること

- MCAP の Header、Schema、Channel、Message、Data End、Footer、マジックとバイト境界を読み出し、チャネル対応とソース別 sequence、順序、重複、欠番を確認する。
- 計画した連番集合を、確定済み記録・理由付き取得前および受理後欠損・Unknown に照合する。未申告欠損、重複、破損、虚偽の損失宣言、未収束 Lease があれば成功として扱わない。異常時に必要な Logger の障害もエラーにする。
- C0 は MCAP のデータ同期、LossLedger と Commit Journal の同期、終了サマリーを確認する。独立 Verifier はグループ境界と成功した連番のメンバーシップを実データと照合する。Prefix CRC が必要なソースではその値をバイト列と照合する。
- Loss-only の正常終了で確認できるのは、同期済みの完了サマリーと同期済みの MCAP・LossLedger が一致すること。クラッシュ中間点の成功フレームを証明するメンバーシップは持たない。実験版は従来のパスに空の Commit Journal を置き、終了サマリーに方式を記録する。将来の公開仕様には方式・必須ファイル・終了サマリーの発行条件を明示する。
- 電源断時のファイル名・ディレクトリの永続性は掲載手順に依存する。実電源断でのデバイスやファイルシステムの動作は、この試験の保証範囲外。

## 異常終了と Unknown

| 構成 | 終了しなかった録画の扱い |
|---|---|
| C0 | Recovery が有効な commit 証拠と範囲を独立に照合できたフレームだけ確定。残りの読み出せるフレームは回収候補で、永続化 Unknown |
| C1 | Data Section CRC は安全に閉じたMCAPの整合性検出に使用できる。クラッシュ後の独立したグループ証拠がないため、読み出せるデータも永続化 Unknown |
| C2 | C1 と同じ確定境界。Data Section CRC と Prefix CRC の裏付けもない |
| 同期なし | 全件 Unknown。ページキャッシュから Reader が読めても確定件数0 |

異常終了で読めなくなったシーケンスを、証拠なしに欠損理由へ振り分けない。テストは SIGKILL、書込み失敗と同期失敗を含む。SSDの電源断・ファームウェア障害への耐性は測定していない。Recovery の候補が元データと同一であるとの証拠を持たない場合は、回収済みと確定済みを区別する。

## CRC と独立 Verifier

- Data Section CRC は記録したデータセクション全体を対象とし、保存したバイトの偶発改変を検出する。Commit Journal の Prefix CRC は境界ごとの確定証拠の検証に使う。どちらも暗号学的認証や、センサが正しい値を生成したことの証明にはならない。
- C2 の Data End には規定の **0（CRC利用不可）** を書く。形式・フッター、長さ、チャンネル、連番が保たれた任意ペイロードの改変は、別の保存前ハッシュなどがなければ汎用 Reader から検出できない。C2 では Prefix CRC を使った Recovery も提供しない。[MCAP Data End の仕様](https://mcap.dev/spec#data-end-op0x0f)
- 今回の Mock Verifier は seed・ソース・sequence から期待ペイロードを再生成するため、C2 の単バイト改変も検出した。実センサの不透明な値に対する一般保証には含めない。データ内容の検証と、ファイル化したバイトの事後整合性は別の検査とする。

次段階の合格条件は、現在の構成と同一入力・同一メモリ予算で独立照合に合格し、欠損、期限違反、破損、未申告、異常終了時 Unknown のいずれも増やさず、性能向上が複数試行で再現すること。[Writer 仕様案](writer-spec-proposal.md)
